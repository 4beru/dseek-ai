# DSeek interface languages and display name

Source-only localization update, November 4, 2026, on the local `i18n` branch.

## Scope and boundaries

- The Android display name is **DSeek**. `app_name` supplies the launcher/system label and existing public notification copy. `mobile_brand` supplies the pairing/home headings. The clipboard label also uses `app_name`.
- Package/application ID `dev.dshmobile.app`, Kotlin app/class names, manifest components, themes, source file names, artifact names, storage keys, host/plugin names and notification channel IDs are unchanged. Desktop **DSH** references still mean DeepSeek Harness, not the mobile display name.
- English default resources and neutral Spanish are the only supported app interface languages. Russian resources and the Russian picker option have been retired with owner approval.
- User/agent messages, question text/options, project/chat/model names, file names, paths, code, original upstream error details and deliberately Russian synthetic fixture content are not translated. Existing user-entered labels are not rewritten.
- No new dependency, translation service, network endpoint, architecture change, business rule or data migration is introduced. Notification behavior, privacy and channel identity remain unchanged.

Format argument positions/types, escaped percentages and resource types are preserved. The former hardcoded `FILE` display fallback now uses `mobile_file_type`. The accessible question counter uses the existing localized `mobile_question_step` resource without changing question navigation or answer handling.

## Locale selection

- The existing selector offers **System default / English / Español**, with Spanish shown as **Idioma del sistema / English / Español**.
- The system option retains the existing platform selection and persistence semantics. Compatible system language choices resolve to English or Spanish, with English default resources when none matches.
- Regional tags such as `en-US`, `es-ES` and `es-MX` map to their language option. Presentation formatting preserves the compatible regional locale from the current configuration.
- Dates, times and framework file-size unit labels use the first supported locale in the current configuration, or English if none matches. Canonical timestamps and stored values are untouched.
- An old `ru` pin is treated like any other unsupported pin. It is not silently rewritten and does not falsely select the System option. Resource fallback is used until the user explicitly selects a supported language or System. The existing Android 13+ app/system locale merge remains unchanged.
- `locales_config.xml` declares `en` and `es`. The existing no-language-split setting is retained. The AGP `androidResources.localeFilters` setting restricts packaged app/dependency locale resources to EN/ES, without changing package identity or dependency versions.
- Android-owned permission dialogs, file/photo pickers and share sheets remain system UI. This change does not translate the operating system or third-party apps.
